## Границы маршрутов

- UI: текущие вкладки задаёт `WorkspaceView.axaml`: `Route Map`, `SignalId ↔ Modbus`, `Менеджер тревог`, `Modbus TCP`. Последняя использует `ModbusDemoView`/`ModbusDemoViewModel`. Существование `OpcUaViewModel` не означает наличия OPC UA-вкладки или автозапуска в Workspace; ограничения реализации и тестов — в [10](10-opc-ua-guide.ru.md).
- Definition: начинайте с manager, затем открывайте только нужные mapper/validator/migrator/storage и [RouteMapSettingsViewModel](../../Configurator.Desktop/Workspace/RouteMap/Settings/RouteMapSettingsViewModel.cs) для UI import/export. Версию задаёт `RouteMapConfigurationDocument.CurrentSchemaVersion`; не выводите её из номера исторического гайда.
- SignalId: прикладной интерфейс → Desktop runtime/mapper → infrastructure provider/dispatcher в [Modbus/RouteMap](../../Configurator.Infrastructure.Modbus/RouteMap/). Проверяйте readback и качество отдельно от отправки команды. Физические адреса находятся в `Modbus.DataMap`, а не в RouteMap UI; `Modbus.AlarmMap` и legacy/demo `ModbusDemo.DataMap` имеют отдельное назначение.
- Карточки/TopBar: начинайте с соответствующей VM и панели; переходите в runtime/dispatcher только для задачи команд или readback. Для сохранения параметров используйте маршрут configuration/settings; UI не заменяет PLC interlock.

## Как ограничить чтение и проверку

1. Выполните `git status --short`, выберите одну строку таблицы и один основной гайд. Правила изменения — в [AGENTS.md](../../AGENTS.md), общие соглашения — в [05](05-coding-rules.ru.md).
2. Откройте начальный файл, найдите нужный символ через `rg -n`, затем его непосредственный вызов/реализацию и тест. Каталог ищите через `rg --files`; не сканируйте всё решение, если владелец уже известен.
3. Расширяйте чтение при доказанном переходе между слоями, изменении контракта или пробеле покрытия. В таблице указаны ориентиры покрытия, а не доказательство всех сценариев; отсутствие отдельного класса тестов не доказывает отсутствие косвенных проверок.
4. Сначала запускайте именованный тест или профильный проект по [06](06-testing-and-diagnostics.ru.md). Для schema/DI/cross-layer/packaging нужны более широкие проверки по `AGENTS.md`. UI-тесты здесь headless; они не заменяют platform smoke.
5. Протокольные проверки — mocks/loopback. Внешний промышленный endpoint и live PLC-команды требуют явного разрешения и установленной среды. Не запускайте приложение для простой проверки Markdown.
6. Исторические материалы открывайте только по правилам [master-индекса](00-master.ru.md); фактический контракт подтверждают код и тесты текущей ветки.
