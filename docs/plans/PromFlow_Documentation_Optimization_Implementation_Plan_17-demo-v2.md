## 1. Цель и измеряемые критерии успеха

### 1.1. Цели

1. **Сократить постоянный контекст Codex**, не утратив правил безопасности и технических инвариантов проекта.
2. **Упростить README**: пользователь должен за 1–2 просмотра понять назначение, границы функций, установку, запуск, путь к документации.
3. **Исключить противоречия** в версиях схем, названиях экранов, путях конфигурации и описании OPC UA.
4. **Дать агенту короткий маршрут «задача → руководство → исходник → тест»**, чтобы сократить чтение нерелевантных файлов.
5. **Разделить текущие контракты и исторические заметки**, а также явно указать единственный источник истины для каждого факта.
6. **Автоматизировать дешёвые проверки** внутренних ссылок, файлов изображений и согласованности терминов.
7. **Измерить результат**, сравнив одинаковые задачи до/после оптимизации, не выдумывая проценты экономии токенов.

### 2.2. Иерархия источников истины

1. **Фактический контракт/поведение:** код, профильные тесты, действующая версия схемы и runtime-конфигурация текущей ветки.
2. **Правила изменения проекта:** краткий `AGENTS.md`, без копирования десятков страниц предметной документации.
3. **Актуальная навигация:** `AgentDocs/ru/00-master.ru.md`, затем актуальные тематические руководства `01`–`12`.
4. **Описание для людей:** `README.md`; не источник низкоуровневых Modbus или OPC UA контрактов.
5. **Справочные исторические тексты:** `AgentDocs/source/ru/` — не считать действующим контрактом без сверки с кодом.
6. **Английские документы:** поддерживаемые переводы/зеркала в пределах их покрытия; при расхождении с RU — проверять код и обновлять оба, явно обозначив неполный перевод.

**Правило для исполнителя:** при конфликте кода и Markdown не менять код под устаревший Markdown; зафиксировать расхождение и исправить текст, если код/тесты подтверждают актуальное поведение.

## 15. Риски и способы предотвращения

| Риск | Вероятный эффект | Как предотвратить |
|---|---|---|
| При сокращении AGENTS потеряются запреты на живые команды | Опасные изменения в будущих задачах | Матрица переноса, safety gate остаётся в AGENTS, независимый review |
| Исполнитель обновит «документацию» путём изменения кода под старый текст | Функциональная регрессия | Docs-only scope, проверка `git diff --name-only` |
| Новый Code Map станет длинным и устареющим | Повторный расход контекста | Только маршруты, не полные описания, обновлять при изменении путей |
| Добавление OPC UA документа заставит считать его готовым через UI | Неверные ожидания оператора | Отдельная секция «видимые функции / код / неподключено» |
| Глобальная замена `ModbusDemo` на `Modbus TCP` | Неверные имена API/config | Менять только UI-текст; сохранять внутренние ID |
| Расхождение RU/EN после правки | Разные инструкции у разных агентов | Сверять изменённые факты в обоих индексах и соответствующих гайдах |
| Внешний линтер начнёт сбоить по сети | Бесполезные CI failures | Внутренние ссылки проверять офлайн, внешние — отдельно |
| Редакционная цель 5–8 КБ приведёт к потере контекста | Снижение качества и безопасности | Не делать размер жёстким критерием приёмки |
| Превращение бенчмарка в live-тест PLC | Операционный риск | Только read-only/code navigation или изолированный loopback |
| Необязательные документы будут созданы «для объёма» | Больше поддержки и потенциальных противоречий | `12`/ADR/operator guide создавать только при обосновании |
| Наследие `16-demo-v1` останется жёстко зашито в AGENTS | Неверная ветка для Codex | В AGENTS относиться к активной ветке из git, а не фиксировать старый номер |
